Módulo 1 — Linux para Ciberseguridad: Consola, Permisos y Errores

Introducción: la terminal como herramienta de seguridad

La terminal no es tu enemiga — es tu interfaz directa con el sistema que estás protegiendo.

En ciberseguridad, la terminal es tu herramienta principal. Las herramientas gráficas son útiles, pero cuando necesitas analizar logs de 10,000 líneas, verificar integridad de archivos, o responder a un incidente en producción, la terminal es la única opción confiable.

Este módulo te da las bases de Linux desde la perspectiva de un profesional de seguridad: no solo “cómo usar comandos”, sino por qué cada concepto de permisos, FHS y shell es relevante para defender sistemas.

Por qué Linux en ciberseguridad: El 90% de los servidores del mundo corren Linux. Los firewalls, routers, dispositivos IoT y servidores cloud usan Linux. Si no dominas la terminal, no puedes auditar, responder incidentes ni automatizar defensas.

La consola Linux: shell, prompt, PATH

¿Qué es bash? ¿Qué es un shell?

Un shell es un programa que toma tus comandos y se los da al sistema operativo. Es la “cáscara” (shell = cáscara en inglés) que separa al usuario del kernel.

Bash (Bourne Again SHell) es el shell más común en Linux. Es el que vas a usar en este curso.

El prompt: estudiante@lab:~$

Cuando abres una terminal, ves algo como:

estudiante@lab:~$

Ese texto se llama prompt y te dice tres cosas:

Parte Significado
estudiante Tu nombre de usuario actual
lab El nombre de la máquina (hostname)
~ Tu ubicación actual (~ = tu directorio home)
$ Indica que eres usuario normal (si fuera #, serías root)

Advertencia de seguridad: Si ves # al final del prompt, significa que estás como root (administrador). Con grandes poderes vienen grandes responsabilidades. Un comando mal escrito como root puede dañar todo el sistema.

Navegación básica

# ¿Dónde estoy?
pwd
/home/estudiante
# ¿Qué hay aquí?
ls
Documentos  Descargas  Escritorio  notas.txt
# Ir al directorio Documentos
cd Documentos

# Volver al directorio anterior
cd ..

Estructura jerárquica de directorios

Linux organiza todo en una estructura de árbol invertido. Todo empieza en la raíz / y se ramifica.

El árbol FHS (Filesystem Hierarchy Standard)

/
├── bin/          ← Comandos esenciales (ls, cat, cp)
├── sbin/         ← Comandos de administración (fdisk, iptables)
├── etc/          ← Archivos de configuración del sistema
├── home/         ← Directorios personales de usuarios
│   └── estudiante/  ← Tu hogar digital
│       ├── Documentos/
│       ├── Descargas/
│       └── Escritorio/
├── tmp/          ← Archivos temporales (se borran al reiniciar)
├── var/          ← Archivos que crecen: logs, bases de datos
│   └── log/      ← Logs del sistema
├── usr/          ← Programas instalados por el usuario
│   ├── bin/      ← Programas adicionales
│   └── local/    ← Software compilado localmente
├── opt/          ← Software de terceros (empresas externas)
├── dev/          ← Dispositivos (discos, USBs como archivos)
├── proc/         ← Procesos del sistema (en memoria, no en disco)
└── boot/         ← Archivos de arranque del sistema

Analogía de la biblioteca

Imagina que el sistema de archivos es una biblioteca:

Directorio Analogía
/ El edificio completo
/bin La sección de referencia (diccionarios, enciclopedias)
/etc El mostrador de información (configuración del lugar)
/home Las salas privadas de cada persona
/tmp La mesa de trabajos temporales (se limpia cada noche)
/var El archivo histórico (crece constantemente con logs)
/usr La colección general de libros

Nota: En Linux, todo es un archivo. Tu disco duro es un archivo en /dev/. Tu terminal es un archivo en /dev/. Esta filosofía es fundamental para entender cómo funciona el sistema.

Perspectiva de seguridad: En ciberseguridad, /etc es el directorio más crítico: contiene configuraciones de SSH, firewall, usuarios y servicios. Un atacante que modifique /etc/passwd o /etc/ssh/sshd_config puede crear backdoors. /var/log es tu fuente de evidencia forense. /tmp es un riesgo porque cualquier usuario puede escribir allí.

Permisos: teoría y práctica

Usuario / Grupo / Otros

En Linux, cada archivo tiene tres niveles de permisos:

    ┌──────────────────────────────────────────────────────┐
    │            PERMISOS DE ARCHIVO                       │
    │                                                      │
    │   -rwxr-xr--  1 estudiante estudiante  120 Jan 1    │
    │    ─┬───┬───                                        │
    │     │   │                                            │
    │     │   └── Otros (r--): solo lectura               │
    │     └────── Grupo (r-x): lectura y ejecución        │
    │            Dueño (rwx): lectura, escritura, ejecución│
    └──────────────────────────────────────────────────────┘

rwx = 4 + 2 + 1

Cada permiso tiene un valor numérico:

Permiso Letra Valor Significado
Lectura r 4 Ver el contenido
Escritura w 2 Modificar el contenido
Ejecución x 1 Ejecutar como programa

Tabla comparativa de permisos octales

Octal Binario Permisos Uso común
000 000 000 000 --------- Sin permisos (archivo bloqueado)
600 110 000 000 rw------- Archivos privados (claves, contraseñas)
644 110 100 100 rw-r--r-- Archivos normales (dueño edita, otros leen)
700 111 000 000 rwx------- Scripts privados
755 111 101 101 rwxr-xr-x Ejecutables y directorios
777 111 111 111 rwxrwxrwx ⚠️ Todos pueden todo (PELIGROSO)

Advertencia de seguridad: chmod 777 es uno de los errores más comunes y peligrosos. Significa que CUALQUIER usuario del sistema puede leer, escribir y ejecutar ese archivo. NUNCA uses 777 en producción. Si necesitas que un grupo acceda, usa 750 o 770.

chmod simbólico vs octal

# OCTAL: asigna permisos específicos
chmod 755 mi_script.sh
# Dueño: rwx (7), Grupo: r-x (5), Otros: r-x (5)

# SIMBÓLICO: agrega o quita permisos específicos
chmod u+x mi_script.sh    # Agrega ejecución al dueño
chmod g-w notas.txt       # Quita escritura al grupo
chmod o=r privado.txt     # Otros: solo lectura

chown y chgrp

# Cambiar dueño de un archivo
sudo chown profesor notas.txt

# Cambiar grupo de un archivo
sudo chgrp administradores notas.txt

# Cambiar dueño y grupo a la vez
sudo chown profesor:administradores notas.txt

Perspectiva de seguridad: El permiso 600 (rw-------) es el estándar de oro para archivos sensibles: claves SSH, archivos .env, certificados privados. Si un atacante accede a un directorio con permisos 777, puede leer/escribir cualquier archivo. El principio de menor privilegio aplica aquí: solo conceder los permisos estrictamente necesarios.

Comandos esenciales con ejemplos

ls — listar contenido

# Listado simple
ls
Documentos  Descargas  notas.txt
# Listado detallado (permisos, dueño, tamaño, fecha)
ls -la
drwxr-xr-x 2 estudiante estudiante 4096 Jan 1 10:00 Documentos
drwxr-xr-x 3 estudiante estudiante 4096 Jan 1 09:00 Descargas
-rw-r--r-- 1 estudiante estudiante  120 Jan 1 10:30 notas.txt
# Tamaño legible (KB, MB, GB)
ls -lh
-rw-r--r-- 1 estudiante estudiante 1.2K Jan 1 10:30 notas.txt

cat, less, head, tail — leer archivos

# cat: muestra todo el archivo (ideal para archivos pequeños)
cat notas.txt
Hola, este es mi primer archivo en Linux.
# less: muestra archivo con scroll (ideal para archivos grandes)
less /var/log/syslog
# Usa flechas para navegar, 'q' para salir

# head: primeras 10 líneas
head /var/log/syslog

# tail: últimas 10 líneas (útil para logs en tiempo real)
tail -f /var/log/auth.log

sudo — ejecutar como superusuario

# Instalar un programa (requiere privilegios)
sudo apt update

# Editar archivo de configuración del sistema
sudo nano /etc/hosts

Modo nativo (sin Docker): En el contenedor, estudiante tiene permisos NOPASSWD para sudo. En tu máquina nativa, deberás escribir tu contraseña de usuario cada vez que uses sudo. Si no estás en el grupo sudo, añádete con sudo usermod -aG sudo $USER (requiere cerrar y volver a abrir la sesión).

Advertencia de seguridad: sudo te da poderes de administrador. Úsalo SOLO cuando sea necesario. Cada vez que uses sudo, pregúntate: “¿realmente necesito privilegios de root para esto?”

grep — buscar patrones

# Buscar la palabra "error" en un archivo
grep "error" /var/log/syslog
Jan 1 10:30:01 lab kernel: [error] device not found
Jan 1 10:31:15 lab app: connection error timeout
# Buscar sin distinguir mayúsculas/minúsculas
grep -i "error" /var/log/syslog

# Buscar en todos los archivos de un directorio
grep -r "password" /etc/

pipe (|) — encadenar comandos

El pipe toma la salida de un comando y la pasa como entrada a otro.

# Ver procesos y filtrar solo los de nginx
ps aux | grep nginx
www-data  1234  0.0  1.2  nginx: worker process
www-data  1235  0.0  1.2  nginx: worker process
# Contar cuántos archivos hay en un directorio
ls -1 | wc -l
15
# Buscar en logs, ordenar y mostrar los primeros 5
grep "Failed" /var/log/auth.log | sort | head -5

Redirección > y >>

# Guardar salida en un archivo (sobrescribe)
ls -la > listado.txt

# Agregar salida a un archivo existente (no sobrescribe)
echo "Nueva línea" >> listado.txt

Solución guiada a errores comunes

“Permission denied”

Síntoma:

bash: ./mi_script.sh: Permission denied

Diagnóstico:

# Verificar permisos actuales
ls -la mi_script.sh
-rw-r--r-- 1 estudiante estudiante 50 Jan 1 10:00 mi_script.sh

El archivo no tiene permiso de ejecución (x).

Solución:

chmod +x mi_script.sh
# o específicamente
chmod 755 mi_script.sh

Nota: Si el problema es que no puedes acceder al archivo porque no eres el dueño, necesitas sudo o cambiar el dueño con chown.

“Command not found”

Síntoma:

nano: command not found

Diagnóstico:

# Verificar si el programa está instalado
which nano
# (sin salida = no está en el PATH)

# Verificar si existe en el sistema
whereis nano

Solución:

# Instalar el programa
sudo apt install nano

# Si está instalado pero no en PATH
export PATH=$PATH:/ruta/al/programa

“No such file or directory”

Síntoma:

cat: notas.txt: No such file or directory

Diagnóstico:

# Verificar dónde estás
pwd
# Verificar qué hay en el directorio actual
ls

Solución:

# Usar ruta absoluta
cat /home/estudiante/Documentos/notas.txt

# O navegar al directorio correcto
cd Documentos
cat notas.txt

Ejercicios prácticos progresivos

E1: Navegar por directorios y crear una estructura personal

# 1. Ve a tu directorio home
cd ~

# 2. Crea la siguiente estructura:
mkdir -p laboratorio/{scripts,evidencias,notas}

# 3. Verifica la estructura
tree laboratorio

Salida esperada:

laboratorio/
├── evidencias
├── notas
└── scripts
# 4. Crea un archivo de notas
echo "Mi primer laboratorio de ciberseguridad" > laboratorio/notas/dia1.txt

# 5. Verifica el contenido
cat laboratorio/notas/dia1.txt

E2: Crear archivos con permisos específicos

# 1. Crea un script ejecutable
echo '#!/bin/bash' > laboratorio/scripts/saludo.sh
echo 'echo "Hola desde el laboratorio"' >> laboratorio/scripts/saludo.sh

# 2. Dale permisos de ejecución (755)
chmod 755 laboratorio/scripts/saludo.sh

# 3. Crea un archivo privado (solo tú puedes leer)
echo "clave_super_secreta_123" > laboratorio/evidencias/secretos.txt
chmod 600 laboratorio/evidencias/secretos.txt

# 4. Crea un archivo de lectura pública
echo "Este es un informe público" > laboratorio/evidencias/informe.txt
chmod 644 laboratorio/evidencias/informe.txt

# 5. Verifica los permisos
ls -la laboratorio/scripts/ laboratorio/evidencias/

Salida esperada:

laboratorio/evidencias/:
-rw-r--r-- 1 estudiante estudiante   28 Jan 1 10:00 informe.txt
-rw------- 1 estudiante estudiante   24 Jan 1 10:00 secretos.txt

laboratorio/scripts/:
-rwxr-xr-x 1 estudiante estudiante   50 Jan 1 10:00 saludo.sh

E3: Usar pipes para filtrar salida de comandos

# 1. Ver todos los procesos del sistema
ps aux | head -5

Salida esperada:

USER       PID %CPU %MEM    VSZ   RSS TTY      STAT START   TIME COMMAND
root         1  0.0  0.1 169316 11632 ?        Ss   09:00   0:01 /sbin/init
root       234  0.0  0.2  72340  5632 ?        Ss   09:00   0:00 /usr/sbin/sshd
estudiante  567  0.0  0.1  12340  2340 pts/0    Ss   10:00   0:00 -bash
# 2. Filtrar solo procesos de ssh
ps aux | grep ssh | grep -v grep
# 3. Contar cuántos archivos .txt tienes en laboratorio
find laboratorio -name "*.txt" | wc -l
# 4. Buscar archivos modificados hoy
find laboratorio -mtime -1 -ls

Notas de seguridad: principio de mínimo privilegio

El principio de mínimo privilegio establece que un usuario o programa debe tener SOLO los permisos necesarios para realizar su tarea — ni uno más.

¿Por qué importa?

    ┌──────────────────────────────────────────────────────┐
    │  SIN MÍNIMO PRIVILEGIO          CON MÍNIMO PRIVILEGIO│
    │                                                      │
    │  chmod 777 script.sh         chmod 750 script.sh     │
    │  ┌─────────────────┐        ┌─────────────────┐     │
    │  │ Cualquiera puede│        │ Solo el dueño y │     │
    │  │ leer, escribir, │        │ su grupo pueden │     │
    │  │ ejecutar         │        │ ejecutar        │     │
    │  └─────────────────┘        └─────────────────┘     │
    │         │                          │                 │
    │         ▼                          ▼                 │
    │  Si un atacante               Si un atacante        │
    │  encuentra el script,         encuentra el script,  │
    │  puede modificarlo            no puede modificarlo   │
    │  para ejecutar malware        (solo lectura)        │
    └──────────────────────────────────────────────────────┘

Aplicación práctica

  • Un servidor web debe correr como usuario www-data, no como root
  • Un script de backup necesita lectura, no escritura
  • Un archivo de contraseñas debe ser 600 (solo el dueño lee)

Advertencia de seguridad: Cada permiso que otorgas es una puerta que abres. Pregúntate siempre: “¿quién necesita acceder a esto y qué necesita hacer?”
